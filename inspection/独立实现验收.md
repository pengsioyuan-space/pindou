# 独立版本验收记录

## 已确认的用户决策

- 无法获得原站源码，改为补齐可运行的独立实现。
- 卡密不是去掉，而是建立站长自己的新系统。
- 首次激活开始计时，每张卡最多绑定 2 个浏览器。

## 实现与验证

- 10 项 Node 测试通过：第一/第二/第三浏览器、并发激活、有效期、停用/恢复、重置、不跨卡访问、输入校验、尝试频率、图像引擎及大图纸编码。
- 服务端 `UPDATE ... RETURNING` 原子分配两个绑定槽位；SQLite 事务测试通过。
- 首次 schema 由 Drizzle 生成，包含 cards、sessions、projects、rate_limits，已检查 SQL；本地迁移执行成功。
- Worker 输出验证包含 callable `default.fetch`；首页、后台和资源响应正常；未验证卡密不能取得编辑器模块。
- 本机 HTTP 流程通过：首页、未激活拒绝加载编辑器、管理员登录、生成测试卡、激活后取得编辑器模块。
- 不使用原站卡密、原站接口、第三方统计或原站密钥。
- 自定义色板、图像转换、PNG 输出的实际浏览器交互仍待验收；浏览器控制工具连接失败。
- WebMCP 仅在浏览器支持时注册；尚无可用验证上下文，未声明验证通过。

## 与原站的差异

这是独立工程，不保证与原站算法逐像素一致。保留主要编辑和导出流程，但未复现原站全部高级模式（魔棒、框选、描图）及账号/手机号/购买系统。品牌映射来自保存件的 291 个颜色；没有虚构原站未确认的预设配色组。

## 回滚与数据维护

原 `snapshot/` 不改动。新版本可通过 Git 提交回滚代码；生产数据库先备份再变更，已经应用的迁移需追加修正。恢复较旧代码前要确认它兼容新 schema。

本地 `.local/` 包含数据库、管理密钥，须由所有者单独备份，不进入公开仓库。丢失 APP_SECRET 会影响所有既有卡密的验证，因此必须和数据库一同保留。
